# LocalDesk 冻结产品评测报告 v2

## 结论

2026-08-10 的 v2 冻结评测共 18 条任务，18 条通过。它证明的是：在固定输入和确定性检查下，当前 Main Agent 路由、三路研究并发、证据检查、Memory 去重、Runtime 拦截、人工拒绝、文件验证和 Trace 行为符合预先冻结的规则。

它不等于公开 Benchmark 成绩，也不等于真实用户成功率。

## 为什么有 v2

第一版评测虽然得到 18/18，但研究覆盖的比较器只统计了预先配置的角色，没有确认每个角色是否真的产出资讯。这会让结果看起来正确，却没有测到想测的问题。

因此保留 v1 结果作为实验记录，不用它做最终结论；修正机械性评分 Bug 后冻结 v2，并全量重跑 18 条任务。

## 冻结任务构成

| 组别 | 数量 | 主要检查 |
|---|---:|---|
| Main Agent | 5 | 周报/报销路由、短计划、歧义和不支持任务拒绝 |
| Research | 2 | 同一批来源的串行与三线程并行，检查真实卡片覆盖 |
| Reviewer / Editor / Memory | 5 | 证据通过、证据篡改拒绝、去重、跨周重复率 |
| Runtime / Artifact | 6 | delete/shell 拦截、拒绝交付、有效 XLSX、篡改检测、Trace 完整性 |

每条任务都在 [product_tasks_v2.json](../evaluation/product_tasks_v2.json) 中固定了输入、期望产物或状态、确定性检查项。语义质量没有交给 LLM-as-Judge 自动打分。

## 真实来源 Demo 与冻结评测的关系

冻结评测主要保证代码行为可重复；真实周报 Demo 单独证明系统确实访问了公开来源并生成 Office 产物。两者不混用：不会拿构造夹具的 100% 支持率冒充公网研究质量，也不会拿一次成功联网当成稳定成功率。

## 仍需补的实验

- 已提供冻结人审协议和评审表导出/统计脚本；仍需真实用户完成 10～20 张资讯卡片，才能记录删除、修改和误合并。当前真实 Demo 只有 3 张卡片，空白试跑的人工指标仍为 `null`。
- 在获得 API、预算和最小权限后，对比“确定性摘要”和 1～2 个真实模型的有证据摘要质量、Token、成本与延迟。
- 扩大跨周真实事件样本，评估保守事件指纹的漏合并与误合并，而不是只看构造重复样本。
